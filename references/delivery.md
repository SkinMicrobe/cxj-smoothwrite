# 成品、验证与公众号使用

## 输出

默认对用户只呈现本篇最终 HTML 的链接和简短使用说明。用户提供 PDF 与期刊截图后，下列中间资料由代理自行完成，不要求用户手动填写或拼装；没有额外发布指令时，生成 HTML 即完成本次工作流。

- `preview.html`：分享给教授的可编辑单文件。包含全部图片、二维码及原文页图，不依赖旁边的assets目录。
- `body-article.html`：去掉工具栏和编辑控件的正文素材。原文区可横向滚动，但不承诺微信保留交互。
- `article.md`：标题、团队导语和概述文字稿。
- `paper_metadata.json`：核对后的真实书目信息及原文指纹。
- `evidence-map.tsv`：正文主张与PDF文件页码的对应。
- `review_notes.md`：来源、实际完成的检查及待补素材；保留“未完成视觉验收/微信手机预览”的实际状态。
- `assets/paper-pages/`：全部原文页图，供公众号素材上传使用。
- `output_manifest.json`：相对路径、文件大小、SHA-256及自动检查结果。

## 检查

自动检查验证文件完整、图片内嵌、原文页图数、输入PDF哈希、证据页码范围和模块结构。它不证明结论正确、截图真实来源、通讯身份准确或视觉排版通过；这些由阅读和实际预览确认。

浏览器可用且目标允许访问时，查看桌面及约390px宽度。检查：标题/长英文换行；只有原文区横向滚动；末页翻阅及跳转；期刊截图放大；文字、照片编辑；下载后重新打开；导语位置和已删除模块。工具不允许某URL时停止该路线，不把安全限制写成需要不断换浏览器解决的故障。

## 微信后台

1. 可尝试“复制正文排版”粘贴进公众号编辑器，重新上传图片并检查样式。
2. 不依赖公众号执行HTML中的JavaScript或保留data URI图片。原文页图应通过微信当前支持的滑动/SVG组件或排版工具配置，所选工具的实际能力须当时核实。
3. 保存为草稿并在手机端检查段落、头像、二维码和左右滑动；仅浏览器中可翻页不算微信验证通过。
4. 未获明确授权时，不自动操作公众号登录、导入、群发、发邮件或GitHub推送。

发送给教授时优先给HTML文件与一行“下载后用电脑浏览器打开”。未测试手机微信内置文件预览时不保证其直接支持。正文里的“下载原文PDF”是可选动作，单文件HTML不因旁边缺少PDF文件而影响内嵌页图浏览。
